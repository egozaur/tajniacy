# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Language

Always respond to the user in Polish (zawsze odpowiadaj po polsku).

## Project

"Tajniacy" is a Polish-language Codenames-style party game. It is static HTML pages (`index.html` TV host, `captain.html` captain phone, `duo.html` two-player mode) plus the shared `common.css` (theme variables), `common.js` (`fitCards()`), `words.js` (`DEFAULTS`: built-in word categories, a plain script global), `tj.css` (the whole shared look: buttons, 3D cards, effects, theme backgrounds, splash, dialogs), `fx.js` (shared effects as plain-script globals: `Snd` sound module, `calm()`, `illus()` card art, `celebrate()`, `bulletScar()`) and `net.js` (`TJNET`: connection to the shared PL3Y server), with no build step and no dependencies to install. The server side (Cloudflare Worker `pl3y-server`, Durable Objects `TjRoom` and `TjSaves`, its unit tests) lives in the `egozaur/mafia` repo under `worker/src/tajniacy/`; keep both sides of the protocol in sync. The UI text and code comments are in Polish, so keep new UI strings in Polish.

It is deployed via GitHub Pages at `https://pl3y.pl/tajniacy/`. The domain belongs to the PL3Y game lobby (repo `egozaur/egozaur.github.io`), and the old `egozaur.github.io/tajniacy/` address redirects there. There is no Node or Python on the dev machine: serve the folder with `dev/serve.ps1` (port 8090). `dev/e2e.html` is an end-to-end test against the real server (host + two captains in iframes; needs `ALLOW_LOCALHOST="true"` in the Worker); run it in real-time headless Edge with `--enable-logging=stderr` and read `E2E RESULT`. The captain QR codes always point at the hard-coded production `BASE_URL`, so changes to `captain.html` only show up on phones after they are pushed.

## Architecture

### `index.html`: host app (shown on a shared screen/TV)
- Lines ~25–2320 are a vendored copy of the `qrcode-generator` library (MIT, Kazuhiko Arase). Don't edit it. The CSS lives in `tj.css` (shared with `duo.html`, so a visual change there shows in both); the app script follows the library. `Snd`, `illus()`, `celebrate()`, `bulletScar()` and `calm()` come from `fx.js`.
- **Password gate**: the game has no password of its own. `<head>` loads `/auth.js` from the lobby repo, which is the shared PL3Y gate with one password for the whole domain (its contract is in that repo's CLAUDE.md). It is a lock for friends, not security. Locally the file doesn't exist (404), so the game runs without a password. `captain.html` loads it too, with `data-no-idle` (no 30-minute idle expiry mid-game).
- **Back to lobby**: `LOBBY_BTN` (`data-act="lobby"`) appears on the splash screen, in setup and in the board footer. It asks for confirmation through `ask()` before going to `/`. The game state lives in localStorage, so after returning the splash screen offers „Wróć do gry”.
- **Saved games**: shared for the whole PL3Y on the server (`GET /api/tj/saves`, `PUT|DELETE /api/tj/saves/:id`). `localStorage.tajniacy_saves` is the cache, entries `[{id, name, ts, game, cfg}]` (newest first, max 50); changes that could not be sent wait in `tajniacy_saves_pending` (`{put:[id], del:[id]}`) and go out via `flushSaves()`; `refreshSaves()` merges the server list when the dialog opens. `cfg` holds `SAVE_CFG`: players, names, theme, match, score and assassins. `saveGame()` tags the live game with `saveId`/`saveName`, and from then on `syncSave()` (subscribed to both store documents) keeps that save up to date after every move. `newGame()` produces a game without `saveId`, so it isn't saved until the user saves it. `savesDialog()` lists, loads and deletes saves. Loading pushes the game to the room, so captains keep their codes. `/favicon.svg` also comes from the lobby.
- **Room on the server**: `Net` / `ensureRoom()` / `connectRoom()` / `pushRoom()`. The host is the source of truth: every `store.set` of `game`/`config` also sends `{t:'set', game, cfg}` to the room, which forwards the board to the captains. The room (`localStorage.tajniacy_room` = `{code, hostToken, cap:{r,b}, capGame}`) is reused for later games, but the captain codes change with every new board: when `game.id ≠ capGame` (`freshCaps()`), `pushRoom()` sends `rotate:true`, the server issues new tokens, disconnects the old captain phones before broadcasting the board and answers `{t:'caps', cap, gameId}`. This keeps the previous captain (or whoever picks up that phone) from seeing the next key. The QR overlay therefore opens on every new game and on loading a save, and `capUrl()` shows no code until the fresh tokens arrive. Rejoining during the same game (phone slept, page refreshed) keeps working. Without a server the game still works and the QR falls back to the offline payload format. The footer shows the connection (`netBadge()`).
- **Defaults**: theme `noir`, music volume 0.5. A one-time migration (`tj_def_v2`) applied these to existing browsers too.
- **Storage abstraction**: `store` has `sub(name, cb)` / `set(name, obj)` over two documents, `config` and `game`. `init()` uses `makeLocalStore()` (localStorage key `tajniacy_v1`). Always write state through `store.set` rather than mutating and re-rendering alone.
- **State**: `config` holds players, team names, theme, word list text, selected categories, match mode and score. `game` holds the 25 words, the `key` array (`r`/`b`/`n`/`a`), `revealed`, `turn`, `winner` and stats. `ui` holds transient view state.
- **Rendering**: `render()` rebuilds `$app.innerHTML` from string-template view functions (`splashView`, `setupView`, `hostBoard`), then calls `fitCards()` (from `common.js`) to shrink card text until it fits. Clicks go through delegated handlers keyed on `data-act` attributes. Escape user text with `esc()` when interpolating.
- **Cards**: `cardHtml()` builds a 3D card (`.in` holding `.front` and, only for revealed cards, `.back` with an inline-SVG illustration from `illus(k)`). Unrevealed cards never carry key classes, so the key isn't leaked into the DOM. iOS Safari can ignore `backface-visibility` here, so the front face of a revealed card is hidden explicitly (`visibility`, switched at the middle of the flip by the `faceout`/`facein` keyframes). On narrow screens (≤700px) the board gets a fixed aspect ratio and the footer leaves room for the fixed sound buttons. `fitCards(FIT_SEL)` shrinks text on both faces.
- **Effects**: `turnBanner()` (folder + stamp), `assassinScene()` (blackout, shot, skull card, `bulletScar()`), `celebrate()` (falling files/badges), `flapNum()` (split-flap counter), `runCounters()` (count-up stats) and the themed background layer `#fx`. Every animation must be disabled under `prefers-reduced-motion` (CSS media block plus `calm()` checks in JS).
- **Game logic**: `newGame()` deals 9 cards to the starting team, 8 to the other, `8 - N` neutral and N assassins (`config.assassins`, 1–3, set in the setup screen). `reveal(i, actor)` and `endTurn()` hold the turn and win rules.
- **Words**: `DEFAULTS` (in `words.js`, shared with `duo.html`) holds the built-in categories. The user-editable list format is `# Category` lines followed by words (one per line or comma-separated), parsed by `parseWords()`.
- **Sound**: the `Snd` module synthesizes music and SFX with WebAudio (no audio files). Its settings live in `localStorage.tj_snd`.
- **Themes**: `classic`, `noir`, `retro` and `light`, applied via `body[data-theme]` and CSS custom properties defined in `common.css` (shared with `captain.html`).

### Server (sibling repo `../mafia`; only these files matter, ignore the rest of that repo)
- `worker/src/tajniacy/room.js` (DO `TjRoom`): the host page is the source of truth and pushes `{t:'set', game, cfg}`; captains connect with per-team tokens and receive the board. One room serves many games, TTL 7 days. A `set` with `rotate:true` issues new captain tokens, closes old captain sockets with 4401 before broadcasting the new board, and answers the host `{t:'caps', cap, gameId}`.
- `worker/src/tajniacy/saves.js` (DO `TjSaves`, singleton): shared saved-games list.
- Routes: `POST /api/tj/rooms`, `GET /api/tj/rooms/:code/ws`, `GET /api/tj/saves`, `PUT|DELETE /api/tj/saves/:id`. Tests: `worker/test/tajniacy.suite.js`.
- `worker/src/tajniacy/duo-engine.js` + `duo.js` (DO `TjDuo`): the two-player mode, see `duo.html` below.

### `captain.html`: captain's key on a phone (opened from a QR code)
- Live format `#<CODE>.<r|b>.<captain token>`: connects to the room via `net.js`, receives the board, marks revealed cards (✓) and the turn by itself (manual ★/⚠ marks are kept per `tjm_<code>_<game id>`). When the host starts a new board the server closes the socket with 4401 (`revoked`): the page drops the board and asks to scan the new code.
- Offline format: the host encodes the game into the URL hash as `#<team>.<payload>`, where team is `r` or `b`. `payload()` in `index.html` produces `base64url(UTF-8("<25-char key>|<25 words>|<red name>|<blue name>|<theme>"))`, and `decode()` in `captain.html` parses it. **If you change the payload format, change both files together.**
- **Hide key** („Ukryj klucz”) is a toggle: the board switches to the public TV view (unrevealed cards neutral, revealed ones in their colour; offline, cards marked ✓ count as revealed), without key glyphs or ★/⚠ marks, and taps are ignored. The state survives new boards.
- In the offline format there is no sync with the host. Captains track cards themselves with local marks, stored in `localStorage` under `tjm_<hash of payload>`.
- It loads the same `common.css` and `common.js` as `index.html`, so theme changes apply to both pages.
- In the PL3Y home-screen app (`APP`: `display-mode: standalone`) there is no browser Back button, so the tools row starts with „← Lobby” (`.tolobby`, back to `/` after a confirm). Both pages carry the shared app meta tags (see the lobby's CLAUDE.md); players scan captain codes with the lobby's built-in scanner to stay inside the app.

### Layout note
- `#app` has `overflow:clip` (fallback `hidden`): the mouse parallax (`--px/--py` on `.board`) and the hover lift of cards would otherwise push past the window edge and show scrollbars.

### `duo.html`: two-player mode („Gra we dwoje”, Duet-style co-op)
- Two people in separate browsers (desktop or phone), talking on Discord. Entry: the „👥 Gra we dwoje” button on the TV splash (`acts.duo`) or a direct link. Looks like the TV game on purpose: it loads `tj.css` + `fx.js` (same cards, flips, illustrations, theme background, sound/music, turn folder banner, assassin scene with bullet scar, falling files on a win) and adds only a small inline style (green `--g/--gt/--gtx` per theme for agents, clue bar, miss badges). Also loads `common.css`, `common.js`, `words.js`, `/auth.js`. Theme and custom word list come from the TV game's `tajniacy_v1` in the same browser.
- Flow like Kurczacze Imperium: menu (nick, create room / join by code) → invite link `duo.html#CODE` asks for a nick → room with tabs **Pokój** (code, copy link, seats with online dots, host ★ picks the turn limit 9/11/none and word categories, Start) and **Zasady** (rules; also in the menu and as a dialog during the game) → board.
- Rules (enforced by the server): shared 25 words, each player has their own key: 9 agents, 3 assassins, 13 neutral; 3 agents shared, 15 distinct in total; one assassin of each key is an agent on the other, one is shared, one is neutral on the other. The giver types a clue + number (1–9). The clue is **one word** (no whitespace; the input strips spaces) and must not equal, contain or be contained in any board word (`clashWord()`, same rule in `duo-engine.js` and `duo.html`). The other player clicks words (confirm dialog „Odsłonić to hasło?”), checked against the **giver's** key, with **exactly n tries** (no +1): agent → found (green), continue; neutral → `miss[giver][i]` (badge „✕ name”, still possibly an agent for the other key), turn ends; assassin → loss. A found card keeps the viewer's own key on its back (`my-g|a|n` class, glyph ▲/☠/●, dark ring for ☠). „Koniec tury” ends guessing early; „Poddaj się” ends the game. A player whose agents are all found stops giving clues. Win at 15 found; loss on assassin, turn limit or surrender. After the end both keys are visible (toggle Mój / partner).
- Words are chosen by the client: the starter sends 25 random words from the selected categories (`tjduo_cats`); the custom list and theme come from the TV game's `tajniacy_v1` config in the same browser, otherwise `DEFAULTS`. After a game ends either player can start a new one („Nowa gra”).
- Storage: seat token `tjduo_<p|l><slot>_<CODE>` (refresh/return resumes), nick `tjduo_nick`.
- Server: `worker/src/tajniacy/duo-engine.js` (pure engine: `setup`, `apply`, `view`; `view` sends only the own key, the partner's key only after the end) and `worker/src/tajniacy/duo.js` (DO `TjDuo`, 2 seats, TTL 3 days). Routes `POST /api/tj/duo/rooms`, `GET /api/tj/duo/rooms/:code/ws`. Protocol: `→ {t:'hello', join|player}`, `{t:'cfg', turns}` (seat 0), `{t:'start', words:[25]}`, `{t:'move', id, act}` with `{a:'clue', word, n}` / `{a:'guess', i}` / `{a:'end'}` / `{a:'surrender'}`; `← {t:'welcome'}`, `{t:'state', view}`, `{t:'error'}`. Tests `worker/test/tajniacy-duo.suite.js`.
- Local testing without Cloudflare: `powershell -ExecutionPolicy Bypass -File dev\serve-duo.ps1` serves the parent folder on port 8094; `http://localhost:8094/tajniacy/duo.html?local=1&slot=1` (second player: invite link + `&slot=2`). `dev/duo-local.js` (SharedWorker) runs the real `TjDuo`. E2E: `http://localhost:8094/tajniacy/dev/duo-e2e.html` (two frames play a whole game through real buttons; real-time headless Edge, read `E2E RESULT`); `?stop=rules|lobby|guess|end|kill&view=a|b|g|s` freezes a step full-screen for screenshots (`../kurczacze/dev/cdp-shot.ps1`).
